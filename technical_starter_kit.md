# Стартовый комплект

**5 сентября 2026. RECOMMENDATION.** Это спецификация подготовки, не реализованный starter. По [operating_decisions.md](operating_decisions.md) универсальную инфраструктуру готовим и используем; готовую business logic под конкретное закрытое ТЗ заранее не строим.

**Принцип комплекта:**

> Задача starter — сделать **первый час скучным**, а не двадцатый час лёгким.

Главное, что комплект привозит с собой, — **общий ствол демонстрации**: не относящийся ни к какому challenge сквозной каркас «вход → обработка → результат» с деплоем и reset. После COMMIT он адаптируется под выбранный challenge; ориентир до первого challenge-specific задеплоенного пути — примерно 1,5–2 часа. Экраны под конкретное направление заранее не строятся ([operating_decisions §8](operating_decisions.md)).

Опасностей две. Подготовить слишком мало — потратить пятницу на setup. Подготовить слишком много — приехать с внутренней платформой, которую придётся сопровождать вместо решения задачи. Вторая опаснее: незнакомый собственный код в три часа ночи дороже его отсутствия.

**Разрешение не равно приоритету.** Operating decisions §8 перечисляет всё, что *можно* готовить. Ниже — что *нужно*.

## 1. Классификация компонентов

### MUST PREPARE — без этого пятница потеряна

| Компонент | Что именно | Критерий готовности |
|---|---|---|
| Репозиторий и запуск | README на один экран, версии runtime, lockfile, `env.example` без секретов, одна команда запуска | Второй по силе участник поднимает с чистого клона |
| Деплой | Публичный URL, health endpoint, читаемый лог, откат на предыдущую исправную версию | Плохой выпуск заменяется предыдущим за минуты |
| **Общий ствол демонстрации** (generic trunk) | Базовые роутинг и layout, оболочка «вход → обработка → результат», состояния loading / empty / error / success, деплой, reset, generic presentation mode | Общий ствол проходится целиком и задеплоен **до события**. Challenge-specific экраны заранее не строятся |
| Ввод и вывод данных | Загрузка CSV/JSON/файла, схема, fixture, импорт и reset | Повторный demo не оставляет мусорного состояния; есть второй известный вход, а не один |
| AI-адаптер | Одна функция, типизированный вход/выход, timeout, ограниченный retry, счётчик расходов, режим отказа | Отказ модели не ломает экран и виден пользователю |
| Структурированный вывод | Валидация схемы, явная ветка отказа, проверка значений | Невалидный ответ обрабатывается, а не падает |
| Логи и происхождение | Источник, время получения, версия sample у каждого показанного результата | Можно объяснить происхождение любого числа на экране |
| Smoke-тест | Один сквозной тест, который падает, когда ломается демонстрируемый путь | Падает, если сломать ствол намеренно |
| Presentation mode | Предсказуемые примеры, крупный шрифт, скрытые секреты, reset одной кнопкой | Демо воспроизводится на втором ноутбуке и способно показать не-fixture поведение |
| Каркас сдачи | Папки под deck, видео, описание, ссылки, инструкцию запуска | Заполняется, а не создаётся в воскресенье |

### PREPARE IF TEAM KNOWS IT — только при живом опыте в команде

PostgreSQL и миграции (иначе SQLite); знакомый auth-путь; карта с точками и одним маршрутом; графики и harness временных рядов; вынесение строк UI для RO/RU/EN.

Критерий один: **кто-то в команде делал это в проде или на хакатоне и может починить без документации**. Иначе компонент переезжает в следующую категорию.

### MODULE ON DEMAND — отрепетировать один раз, положить на полку, не подключать

RAG (разбиение → поиск → цитата → отказ при отсутствии); OCR и извлечение текста из PDF; прогнозный baseline (seasonal naive + одна модель); гео и маршрутизация; речь.

«Отрепетировать» — значит один раз пройти путь на реальном файле и сохранить рабочий пример вне основного репозитория. Модуль подключается после reveal, если brief этого требует.

### DO NOT PREBUILD

Доменная модель данных и бизнес-логика неизвестного партнёра; собственный gateway на несколько LLM-провайдеров; система плагинов; mesh агентов; микросервисы; event bus; Kubernetes; новая дизайн-библиотека; собственная система паролей; всё, что никто в команде не запускал.

Исторический монорепозиторий победителя показывает, что такое решение существовало, а не что его нужно повторить.

## 2. Acceptance-тесты всего комплекта

Комплект считается готовым, когда выполняются все четыре.

1. **Холодный клон.** Второй по силе участник, на своей машине, с нуля: локальный запуск ≤ 10 минут, публичный URL ≤ 20 минут.
2. **Отказ.** Внешний API выключен — интерфейс объясняет состояние, действие не дублируется, есть честный запасной показ.
3. **Повтор.** Reset возвращает данные в исходное состояние; демонстрационная история не попадает в метрики.
4. **Чужой браузер.** Публичная ссылка проходится с другого ноутбука и из отдельной сессии с теми правами, которые получит судья.

### Протокол фактической верификации

**Тест на избыточность.** Если в стартовом репозитории есть код, который никто из команды не открывал последнюю неделю перед событием — он удаляется. Размер репозитория не является показателем готовности.

**Что комплект обслуживает.** Способности готовятся под Tier A (Orange, Smart City, AgriFood) и Tier B (Energy, Medpark). На Open Challenge и оба cybersecurity-направления starter-бюджет не тратится: инструменты Red/Blue, DFIR и threat hunting в комплект не входят.

## 3. Выбор стека

| Условие | Предпочтительный путь | Ограничение |
|---|---|---|
| Команда уверена в TypeScript, продукт — web workflow | Next.js + server-side API + одна БД при необходимости | Route handlers требуют продуманного доступа; ограничения runtime зависят от деплоя |
| Главная ценность — Python data/ML | Vite/React UI + FastAPI | Два процесса и контракт между ними должны быть знакомы до события |
| Один сервер, небольшой прототип без конкурирующей записи | SQLite на постоянном диске | Не переносить предположение о локальном файле на несколько serverless-инстансов |
| Несколько пользователей или знакомый managed backend | PostgreSQL / проверенный сервис | Миграции и права проверены; не изучать новую BaaS в пятницу |
| Мобильные возможности по brief | Знакомая mobile-команда или web/PWA | PWA не даёт автоматически всех OS-интеграций |

**FACT:** Next.js route handlers дают HTTP endpoints; FastAPI формирует OpenAPI; SQLite допускает одного writer одновременно. [Next.js](https://nextjs.org/docs/app/guides/backend-for-frontend), [FastAPI](https://fastapi.tiangolo.com/tutorial/first-steps/), [SQLite](https://www.sqlite.org/whentouse.html).

**Один скучный надёжный стек лучше максимальной способности.** Размещение выбирается по факту успешного drill, а не по обещанию бесплатности: проверить план, длительность запросов, постоянный диск, фоновые задачи и доступ жюри. Доступность конкретного тарифа этим исследованием не подтверждена; покупок и деплоя оно не выполняло.

**Аутентификация.** Не строить свою систему паролей. Если идентичность не нужна основному сценарию — явно обозначенная demo-роль при безопасном публичном доступе, без настоящих данных. Если роли важны — знакомый auth-путь. MPass только при выданном доступе и подтверждённом scope.

## 4. Заметки по модулям на полке

**RAG.** Извлечение текста со ссылкой на страницу, разбиение, простой поиск, отказ при отсутствии ответа. Для малого корпуса сначала обычный поиск; отдельная vector DB — когда без неё не проходит задача. Качество поиска проверять до улучшения генерации. Fine-tuning по умолчанию не включать.

**OCR.** До события проверить один реальный тип файла: скан, PDF с текстовым слоем, таблица или фото. Дать оператору исправить распознанное. Не обещать точность на всех документах по двум образцам.

**Карты.** Точки и один маршрут из разрешённого GeoJSON. Отдельно проверить tiles, лицензию, attribution и правдоподобие данных. Полная GIS-платформа не нужна. [Ресурсы Молдовы](moldova_resources.md).

**RO/RU/EN.** Вынести строки, даты и валюты; подготовить формулировки с диакритикой, вариантами адресов и пустыми переводами. Для локального workflow первичен язык пользователя; для pitch держать короткую EN-версию.

**Прогноз и оптимизация.** Переиспользуемая способность Tier A/B: загрузка рядов, единицы, пропуски, разбиение по времени, простой baseline. Погода не заменяет показаний счётчиков; агрегатная статистика не заменяет событий отдельного объекта.

**Речь.** Только если голос снимает реальное ограничение пользователя, и никогда как единственный вход.

## 5. Что остаётся на после reveal

Схема БД под задачу, бизнес-логика, документная модель, выбор целевой переменной, роли пользователей, внешний auth, телеметрия эффекта. Заготовить можно способ быстрой реализации; модель данных неизвестного партнёра заранее обычно оказывается неправильной.

На событии зафиксировать, что было подготовлено заранее, что создано в разрешённый период и какие компоненты сторонние. Исходная версия starter сохраняется отдельным тегом до старта.

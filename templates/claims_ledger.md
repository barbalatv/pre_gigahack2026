# Реестр утверждений

Один лист. Ведёт **proof owner**. Правило: **любое утверждение, которое прозвучит на защите или появится на слайде, должно быть в этой таблице.** Если строки нет — утверждение не произносится.

Challenge ______ · Версия продукта ______ · Дата и время последнего обновления ______

**Типы утверждений**

- **измерение** — есть набор, baseline и процедура. Обязателен знаменатель.
- **демонстрация** — показывается на экране здесь и сейчас. Обязательна воспроизводимость с холодного старта.
- **ссылка на владельца** — «владелец задачи подтвердил, что…». Обязательны имя и дата разговора.
- **roadmap** — то, что мы **не** сделали. Произносится только в будущем времени.

**Правила**

1. Процент без знаменателя запрещён. «На 18 из 20 согласованных примеров» — можно.
1a. Форма проверки выбирается под тип задачи: набор дискретных случаев для RAG, извлечения, классификации и действий; разбиение по времени и наивный baseline для прогноза; целевая функция и ограничения для оптимизации; воспроизводимые сценарии для маршрутов.
2. Набор для настройки и набор для отчёта — разные; указать, какой использован.
3. Синтетические данные называются синтетическими в той же фразе, где звучит число.
4. Один провальный случай включается в реестр намеренно и показывается на защите.
5. Право удалить любое утверждение из реестра есть у каждого участника; вернуть его может только доказательство.

**Проверка перед защитой:** взять список утверждений, задать по каждому вопрос «откуда вы это знаете?» и ответить только по столбцам таблицы. Утверждение, на которое нельзя ответить из таблицы, снимается.

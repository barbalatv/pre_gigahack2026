## Acceptance Gates

Короткая проверка по [team_rehearsal §4](../team_rehearsal.md); модель fork/upstream не обязательна для общего repository/worktree.

- [ ] **Gate A — Fresh base:** отдельная ветка создана от актуального основного `main`; starting/base SHA записан точно.
- [ ] **Gate B — Scope:** полный diff от base просмотрен; только write scope, без старых задач, generated-файлов и случайного форматирования.
- [ ] **Gate C — Behaviour:** положительный и отрицательный / граничный сценарии проверены; ствол проходит на объединённой версии.
- [ ] **Gate D — Ownership:** человек-владелец объясняет каждый изменённый файл и причину изменения одним предложением.
- [ ] **Gate E — Handoff:** ветка, commit и PR названы понятно; результат содержит изменения, проверки и evidence; при паузе заполнена Branch Pause Note, готовность не заявлена.

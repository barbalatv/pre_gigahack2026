# GigaHack 2026 — canonical research synthesis

Аудитория: одна основная onsite-команда из пяти человек. Дата среза: 5 сентября 2026. География: Молдова; история 2023–2025 и опубликованное издание 2026. Решение: как организовать подготовку одной команды, чтобы максимизировать вероятность её победы в одном выбранном challenge. Пятеро называются до 10 сентября; рекомендации для software-команд условны. Формат: Markdown. Это внутренний источник синтеза; основной вход для команды — Executive Brief.

## Прямой ответ

**Обновление по operating_decisions.md v2.1, 05.09.2026.** Baseline — одна onsite-команда, **ровно пять человек**, один challenge. Прежний вариант «2–3 команды» архивирован. Пять мест: Integrator, Technical Deputy, Product/Domain, Data/Evaluation/Reliability, UX/Demo/Surge; у каждой зоны заместитель. Активный AI при уточнённой формулировке: паритет доступа к моделям, но не паритет оркестрации. Целевые направления: Tier A — Orange, Smart City, AgriFood; Tier B — Energy, Medpark; Open Challenge и оба cybersecurity-направления NOT TARGETED. Планировочное допущение — трек может быть заполнен полностью, до пяти других серьёзных команд.

**RECOMMENDATION.** Выбирать challenge по восьми критериям: пользователь, sample, валидатор, baseline, оценимость утверждения, показ за 60–90 секунд, соответствие пятёрке, выполнимость зависимостей; плотность конкуренции вторична. Около T0+3ч — точка обязательства, после неё смена только при жёстком блокере. Общий ствол привезти готовым; после COMMIT получить первый challenge-specific задеплоенный путь примерно за 1,5–2 часа; к Friday Exit Gate иметь узкий задеплоенный сквозной путь, при угрозе — резать scope, а не растягивать ночь. К субботе 14:00 — развёрнутый продукт, baseline и доказательства; 18:00 — feature freeze; воскресенье 12:30 — запись финальной версии; 14:00 — отправка. Подготовка — шесть коротких drills, полных репетиций нет.

## Почему это поддерживается источниками

**FACT.** Нынешняя agenda разделяет track judging и последующее выступление победителей. Это делает убедительность для небольшой профильной комиссии первичной задачей защиты. Наша внутренняя отправка на час раньше — рекомендация, а не официальный дедлайн. [Agenda](https://gigahack.md/agenda/).

**OBSERVED PRACTICE.** Победитель GovTech 2023 связан с конкретным каталогом госуслуг; его публичная защита объясняет архитектуру, показывает сценарии и признаёт ограничения. Сохранившиеся артефакты других победителей включают мобильный workflow, parking operations, CTF writeup. Единого выигрышного стека не видно. [AGE](https://egov.md/ro/node/40041), [защита 7301](https://www.youtube.com/watch?v=RO0qY_TyPgI), [HEX](https://github.com/LiviuMrc/Gigahack-2024-HEX-team), [FalcoNS](https://github.com/Koyd1/GIGAHACK-2025-FalcoNS).

**INFERENCE.** Наиболее защищаемая модель победы — соответствие задаче, достоверное доказательство результата, ясность представления и реалистичный следующий шаг. Нельзя оценить независимые веса или причинный эффект demo/mentor/языка: нет сопоставимых score sheets и артефактов всех проигравших.

**FACT.** Текущий SOC.MD track описан как Red/Blue Cyber Range. Общий продуктовый playbook не заменяет навыков расследования и защиты. [FCIM UTM](https://fcim.utm.md/aviz/%F0%9F%9B%A1%EF%B8%8F-deeptech-gigahack-4-48-de-ore-de-provocari-in-securitatea-cibernetica/).

**FACT.** Документы eGov открыты, но интеграции требуют регистрации/сертификатов. Два публичных каталога отвечают на read-only запросы; старый пример service code 2023 возвращает 204, текущий код из каталога — 200. Значит, доступность нужно проверять на точном маршруте и данных. [eGov4Dev](https://egov-moldova.github.io/egov4dev/), [категории](https://servicii.gov.md/rsspa-api/catalog/categories), [CKAN](https://dataset.gov.md/api/3/action/package_search?rows=2).

**FACT / ограничение переносимости.** Исследования агентных систем обнаруживают зависимость эффекта параллелизма от структуры задач и коррелированные ошибки разных моделей. Малое исследование AI на хакатоне подчёркивает нехватку времени и компетенций для проверки. Это аргументы в пользу проверки собственной пропускной способности на репетиции, не доказательство оптимальности конкретного числа агентов. [Scaling agents](https://arxiv.org/abs/2512.08296), [Correlated errors](https://arxiv.org/abs/2506.07962), [Hackathon study](https://arxiv.org/abs/2607.29178).

## Существенные исправления baseline

Orbility и SOC.MD — две отдельные cyber-карточки; AgriFood — BioMentor Hub + Profi. Восемь опубликованных карточек не закрывают план десяти, теперь подтверждённый provider form и вакансией. Provider model до шести команд по пять проверен напрямую; минимум, исключения и полный rulebook не установлены. Reuse/AI/collaboration/IP официально UNKNOWN, но внутренние решения по ним приняты. История HEX с одним PDF не доказывает допустимость готового кода. Дополнение — operating_alignment.md; ledger — sources.md. Добавлен FACT: организатор публикует, что каждая участвующая организация оценивает полученные решения; это не доказывает состав жюри.

## Границы результата

Публичное исследование завершено до границы доступных материалов. Не получены текущий полный rulebook, score sheets, весь набор briefs, финальная Airtable-форма, доступы к системам партнёров и состав нашей группы. Репозитории исследованы выборочно, без запуска чужих приложений; текущая ветка может содержать работу после события. Видео 7301 исследовано по экспортированной автоматической расшифровке, не по полному визуальному просмотру. Архивные страницы, participant claims и маркетинг не принимаются за независимую проверку качества.

Не требуется знать все будущие ответы, чтобы завершить подготовительный план: для каждой неопределённости задано условие решения и временная ветка. Организаторам ничего не отправлено. Дополнительный широкий поиск перестал менять приоритеты; дальнейший существенный прирост даст новый brief, ответ организатора или репетиция состава.
